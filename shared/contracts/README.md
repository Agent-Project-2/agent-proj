# 사건 01 · B의 게임 상태와 행동 계약 초안

#5에서 공동 검토할 예시다. [공통 자료](case-01.json)의 caseId, NPC ID, 증거 ID를 사용한다. [검증 요청 예시](action-examples.json)는 게임과 테스트가 같은 결과를 확인하는 입력이다. A가 소유하는 기억·믿음·Skills와 #14의 도구 등록 방식은 공동 검토 대상이다.

## 공개 상태와 권한

게임 쪽 원본은 불변 사건 정의와 세션별 상태를 구분한다. 공개 상태는 세션 ID, 현재 장소, 이튿날의 게임 시각, 탐색 가능한 장소, 현재 장소에서 조사할 수 있는 오브젝트, 네 주민의 공개 프로필·위치·활동, 획득 증거, 주민별 공개 진술 및 이벤트를 담는다. 서버는 현재 세션에서 확보한 증거만 상세 조회·제시에 사용한다. 잠긴 오브젝트는 공개 목록에서 제외한다. 증거 예시 원본과 시나리오 정답 파일은 웹 정적 경로 밖에 둔다.

`gameMinute`는 수사 첫날 자정부터 누적한 분이다. 증거의 `eventTime`은 기록 속 사건 시각이다. 증거에는 작성 출처와 획득 경로 `acquired.{eventId,sourceId,locationId,gameMinute,method}`가 함께 남는다. `interviews[npcId]`의 발언은 발화자를 출처로 하는 진술이다. 제시한 자료의 ID와 발언 시각을 보존한다. 플레이어 화면이나 NPC의 요청으로 사건 진실·현재 시간·획득 증거를 직접 바꿀 수 없다.

## 로컬 HTTP 예시

| 요청                | 의미                                                                                          |
| ------------------- | --------------------------------------------------------------------------------------------- |
| `GET /api/session`  | 현재 브라우저의 공개 상태. 첫 방문에 광장·14시·자백서 E01로 시작한다.                         |
| `POST /api/session` | 화면에서 새 조사를 확인한 뒤 새 세션을 만든다. 기존 브라우저 세션의 기록을 초기화한다.        |
| `POST /api/actions` | JSON으로 `sessionId`, `requestId`, `action`을 보낸다. 쿠키와 세션을 대조하고 행동을 검증한다. |

| action.type                 | 요청 필드         | 검증과 결과                                                                                      |
| --------------------------- | ----------------- | ------------------------------------------------------------------------------------------------ |
| travel                      | locationId        | 등록된 다섯 장소로 이동한다. 승인된 이동만 위치·시각을 갱신한다.                                 |
| inspect                     | objectId          | 현재 장소와 해금 조건을 검사하고 공개 상세·획득 출처를 기록한다. 재조사는 기존 단서를 보여 준다. |
| question, persuade, promise | npcId, text       | 현장에 있는 주민에게 최대 240자의 질문·설득·약속을 전달하고 공개 진술을 기록한다.                |
| present_evidence            | npcId, evidenceId | 해당 주민과 획득 여부를 검사하고 제시한 증거를 진술에 연결한다.                                  |
| end_interview               | npcId             | 현장에서의 면담 종료를 기록한다.                                                                 |

응답은 `{ result, state }`로 돌아온다. 성공 결과에는 `status: "accepted"`, 요청 ID와 공개 메시지가 있으며 상태를 바꾼 행동에는 서버 이벤트 ID가 붙는다. 오는 도중 연결이 끊기면 동일 요청 ID와 같은 내용으로 재전송한다. 승인 또는 규칙상 거절을 다시 처리하지 않으며 최신 공개 상태를 돌려준다. 같은 ID로 내용을 바꾸면 `REQUEST_CONFLICT`다. 다른 세션의 ID는 `SESSION_MISMATCH`, 다른 장소의 주민은 `NOT_HERE`, 미획득·존재하지 않는 증거는 동일한 `EVIDENCE_NOT_ACQUIRED`로 거절한다. 통신 실패 화면은 같은 요청으로 재시도한다.

## 다음 연동

게임 MCP 도구의 B 제안은 현재 장소·게임 시각을 조회하는 `get_world_state`와 획득한 증거를 제시하는 `present_evidence`다. 조사관 권한의 새 세션에서 공개 상태를 읽은 뒤 미획득 E04를 제시했을 때의 요청·응답을 담았다. [MCP 호출 예시](mcp-examples.json)

JSON-RPC의 `id`는 호출과 응답을 연결한다. 게임의 `requestId`는 세션 안에서 재시도를 식별한다. 도구 실행자는 호출 주체의 권한으로 장소·증거를 조회하고, NPC의 진술에는 해당 인물과 명시적으로 공유한 자료만 전달한다. 예시의 성공 데이터와 게임 규칙상 거절은 로컬 게임 상태와 대조할 수 있다. MCP 서버 등록과 실제 전송 검증은 #12의 연동 항목이다.

게임 서버가 면담을 승인하면 인물별 응답 처리기에 [제시한 증거와 NPC 문맥](interview-context.json)을 넘긴다. 예시는 기록관에서 E04를 얻고 광장으로 돌아와 도현에게 처음 제시하는 시점의 실제 입력이다. `previousTurns`에는 현재 주민과 공개적으로 주고받은 발언만 담긴다. `presentedEvidence`에는 제시한 자료 한 건 또는 `null`이 들어간다. 예시 응답 처리기가 실패하면 HTTP 503과 `RESPONSE_UNAVAILABLE`을 반환하며 시각·진술·획득 자료는 응답 성공 시점에 반영한다.

#6은 조사 결과·공개 기록을, #7은 세션·이동·시간과 영속 저장을, #10은 주민별 응답을, #12는 도구 실행 권한을 제공한다. 현재 로컬 서버의 공개 응답만 UI가 소비한다. 서버에 붙이는 실제 NPC 도구는 해당 NPC가 접근할 문맥을 받고 발화·공개·행동을 제안하며, 서버가 허용한 결과만 플레이어에게 전달한다. 예시와 필드 변경은 양쪽이 같은 검증 요청으로 호환성을 검토한 뒤 반영한다.

최종 추리 입력의 B 제안은 세션, 주장, 실제 획득한 근거 ID의 조합이다. 미획득 근거는 동일한 권한 오류로 거절하고, 유효한 주장과 근거의 조합은 서버가 판정한다. 구체 판정 조합은 #3의 검토에 달려 있고 실제 판정기는 #15 범위다.
