# 상세 기능·기술 요구사항

[PRD](../PRD.md)의 상세 요구사항을 기존 ADR에서 분리한 문서다. 새 기술 선택이나 팀 합의 완료 기록이 아니다. PRD는 목적·사용자·플레이 기능을, 이 절은 구현 시 빠뜨리지 않을 상태·권한·연동 조건을 설명한다. 필드명·물리적 저장 위치·전송 방식은 #5에서 공동 검토한다.

| 대상           | 유지할 요구사항                                                                                                                                                                                                                                |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 사건 정의      | 발생 시각·장소, 범인·방법·동기, 실제 시간순서, 주요 증거, NPC별 목격·비밀·거짓 진술과 해결 조건을 서버에서 읽기 전용으로 관리한다.                                                                                                             |
| 세션 상태      | 방문 장소·획득 증거·진술·수첩·시간·NPC 관계·기억·행동 계획·이벤트를 사건 정의와 분리해 저장한다. #7의 생성·조회·초기화·저장·복원, #6의 공개 수사 기록, #9의 NPC 저장 로직을 일관되게 연결한다.                                                 |
| NPC 상태       | ID·프로필·성격·목표·비밀·아는 정보·믿는 정보·기억·방향별 관계·위치·활동·경계심·일정·다음 행동 계획을 유지한다.                                                                                                                                 |
| 기억           | 직접 경험·전달 정보·추측·대화·행동 결과를 구분하고 내용·시점·출처·직접 경험 여부·열람 가능한 NPC·관련 사건을 기록한다. 고의 거짓말과 사실로 믿는 착각을 구분한다. 실수·사생활·타인 보호·불이익 회피 등 정보 은폐 이유를 반영한다.              |
| 관계·판단      | 방향별 신뢰·갈등·보호 의지를 반영한다. 친밀감·이해관계는 상세 설계 검토 항목이다. 게임 안의 질문·반복 추궁·증거·협조 요청·비난·설득·조사 순서·약속 이행/위반·정보 공유를 기록·요약한다. NPC가 자신의 목표·지식·관계·공개 위험과 함께 판단한다. |
| 전달 이벤트    | 발신자·수신자·정보 출처를 보존한다. 수신 NPC의 다음 판단에 반영하며 재처리·재전달 시 중복 기억·행동과 무한 전파를 막는다.                                                                                                                      |
| 요청 가능 행동 | 이동·대화 요청·만남·정보/소문 전달·계획 갱신·증거 제공·정보 은폐·진술 수정을 포함한다. 서버가 접근 권한·현재 상태·행동 가능 여부·사건 일관성을 검증한 결과만 실행·공개한다.                                                                    |
| 판정           | 범인·방법·동기·획득한 관련 증거를 불변 사건 정의와 대조한다. 유효한 서로 다른 증거 조합을 허용하고 미획득·무관한 증거, 범인만 맞힌 제출은 해결로 인정하지 않는다.                                                                              |

연결 순서는 플레이어 행동 요청 → 서버 검증·상태와 이벤트 기록 → 관련 NPC 문맥·Skills 로딩과 판단 → MCP 정보 조회·행동 요청 → 서버 재검증·실행·화면 반영이다. 중요 이벤트에서만 관련 NPC를 호출하며 규칙 기반 일상 이동과 분리한다. 하루 종료와 구체적인 시간량은 미정이다.

도구 이름은 `get_npc_memory`·`get_relationship`·`get_world_state`·`send_message`·`request_npc_action`·`get_accessible_evidence`·수사 기록 추가/조회를 예시로 검토한다. Skills는 `memory-reasoning`·`social-decision`·`interrogation-response`·`information-sharing`·`action-planning`·증거 검증을 예시로 하며 실제 이름·런타임은 확정하지 않았다.

비교 시연은 같은 초기 상태에서 비밀 보호·약속 이행으로 첫 주민의 신뢰를 얻는 경로와, 근거 없는 반복 추궁으로 경계를 높이는 경로를 비교한다. 전달받은 주민이 목표·위험을 다시 판단해 자발적 증언 또는 공개 보류·행동 변화를 보이고, 두 경우 모두 증언이나 물증·기록으로 해결해야 한다. 박물관 보석 도난은 확정 사건이 아닌 예시다.

이전 PRD의 선행 사례 목록(Generative Agents·Wanderfolk·Vaudeville·The Guest·Isla Verde)은 기억·관계·소문·심문·고정 진실을 비교하는 조사 대상으로 유지한다. 검증된 비교 결과나 세계 최초 주장으로 기록하지 않는다. 독창성은 PRD §2의 수사 방식에 따른 정보 전달·행동·단서 경로 변화가 실제 시연과 일치하는지로 확인한다.
