## 설계 원칙

사건의 진실은 고정하지만 해결 과정과 관계는 달라진다. 플레이어는 사건과 무관한 자유 대화도 할 수 있으며 NPC는 중요한 대화를 기억한다. NPC는 자신이 아는 정보만 사용하고 서버가 모든 상태 변경을 검증한다. 공통 엔진은 사건별 데이터와 분리한다.

CASE 01은 삼례 나라슈퍼 사건의 허위 자백, 마르탱 게르 사건의 신분 사칭, 캠든의 기적 사건의 생존한 실종자라는 구조를 차용한 독립 창작이다. CASE 02는 힌터카이펙 사건에서 고립된 공간과 미해결 미스터리의 분위기를 차용할 예정이다. 실제 범행을 재현하거나 실제 피해자·가해자를 캐릭터로 사용하지 않는다.

## 범위 및 승인

현재 main의 공식 MVP는 사건 1개, 핵심 NPC 4명, 장소 3곳이다. 두 사건, 자유 일상 대화, 추가 장소, 개별 에필로그는 검토 제안이며 승인 후 PRD·TodoList·관련 이슈와 정합성을 맞춘다. CASE 01을 먼저 완성하고 CASE 02는 같은 엔진에서 데이터 교체로 확장한다. 파일명·필드명·도구명은 공통 계약 확정 전 예시다.

이 문서들은 개발자 전용 스포일러를 포함한다. 공개 클라이언트 번들 및 NPC 프롬프트에 전체 문서를 넣지 않는다. 문서는 설계 근거이며 실행 데이터의 중복 원본으로 사용하지 않는다.
