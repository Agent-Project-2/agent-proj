# 공통 NPC 시스템 설계

팀 검토용 초안. [기술 요구사항](../technical-requirements.md) 및 [작업 지침](../../AGENTS.md)을 상위 기준으로 삼는다. 신규 기능·필드·도구명·수치는 확정 계약이 아니다.

## 목적

NPC는 증거 제공기가 아니라 사건이 없어도 개인적인 삶을 살아갈 인물이다. 자유 대화에서 형성된 기억과 관계가 심문, 정보 공개, 믿음 수정, 소문 및 자율 행동에 영향을 준다. 사건 진실은 불변이다.

## 상호작용

| 기능           | 동작                                                 |
| -------------- | ---------------------------------------------------- |
| 자유 일상 대화 | 취미, 가치관, 우정, 사랑, 행복, 감정 등 사건 외 대화 |
| 자유 심문      | 자연어 질문으로 사건 정보를 요청                     |
| 증거 제시      | 실제 획득한 증거 ID를 선택하여 전달                  |
| 설득·공감      | 가치관·목표에 맞춰 협조 요청                         |
| 추궁           | 모순 지적, 압박 및 후속 질문                         |
| 정보 공유      | 확인한 증언·사실을 다른 NPC에 전달                   |
| 거짓 주장      | 플레이어의 미검증 주장을 사실과 분리해 처리          |
| 약속           | 약속과 후속 이행·위반을 기억                         |

자유 대화와 심문은 하나의 자연어 입력 흐름을 사용한다. AI가 의도를 분류하되 증거 제시 등 권한이 필요한 행동은 서버가 실제 ID와 획득 상태를 확인한다. 대화가 사건과 무관하더라도 불필요하게 사건으로 되돌리지 않는다.

### 자유 대화 예시

| 질문                                     | 도현                                                | 서윤                                               | 하린                                                             | 재현                                                   |
| ---------------------------------------- | --------------------------------------------------- | -------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------ |
| 사랑하는 사람을 위해 거짓말을 해도 될까? | 그 거짓말 때문에 누가 불행해지는지는 생각해 봐야죠. | 저는 선택할 기회라도 받고 싶은데요.                | 사랑한다는 이유로 모든 걸 말하는 사람이 더 잔인할 때도 있잖아요. | 그 거짓말 속에서 살아온 사람이 판단해야 하지 않을까요? |
| 마을을 떠난다면?                         | 바닷가요. 소금기 때문에 기계가 자주 고장 날 테니.   | 장소를 바꾸는 것과 인생을 바꾸는 건 다른 문제예요. | 누가 제일 먼저 저를 그리워할까요?                                | 아무도 제 이름을 모르는 곳에서 살고 싶습니다.          |
| 언제 가장 행복해?                        | 고친 물건을 찾아가는 사람이 웃을 때요.              | 어려운 문제를 풀고 아무도 방해하지 않는 오후.      | 필요한 게 아니라 보고 싶어서 찾아왔을 때요.                      | 오늘 하루가 기대되는 것. 아직은 잘 모르겠습니다.       |
| 사랑이 뭐야?                             | 나 없이도 잘 살았으면 좋겠다고 생각하는 거요.       | 상대를 정확히 알면서도 곁에 남기로 결정하는 것.    | 내가 없어도 괜찮은 사람한테 내가 필요해지고 싶은 마음.           | 상대가 원하는 자신이 되지 않아도 떠나지 않는 것.       |

예시 대사는 캐릭터 일관성 검증에 쓰며 고정 응답으로 강제하지 않는다.

## 기억

직접 경험, 전달 정보, 추측, 대화 및 행동 결과를 구분한다. 기억에는 ID, 내용, 시점, 출처, 중요도, 직접 경험 여부, 접근 가능 범위, 관련 NPC·사건, 원본 이벤트 ID를 보존한다. 개인 취향·감정·약속도 중요한 경우 저장한다. 반복 대화는 요약·중복 제거하고 관련 기억만 조회한다. 사실과 거짓 주장을 합치지 않는다.

예: 초반 플레이어가 도현에게 “다른 사람을 지키지 못했다고 가치가 사라지는 건 아니야”라고 실제 말한 경우, 후반 자백 철회 시 해당 기억을 회상할 수 있다. “그럼 이번에는 저 자신을 좀 지켜도 되는 겁니까?”라는 대사를 생성할 수 있다. 저장되지 않은 발언을 있었다고 지어내지 않는다. 플레이어의 실제 개인정보 저장이 아니라 세션 내부 가상 대화 기억에 한정한다.

## 관계·감정

관계는 방향별로 관리한다. 기존 요구사항의 신뢰·갈등·보호 의지를 유지하고 친밀감·존중·경계심 및 현재 압박감을 추가 검토한다. 압박감은 일시적인 감정 상태로 분리할 수 있다.

| 지표           | 의미                                   |
| -------------- | -------------------------------------- |
| 친밀감         | 개인적 애정, 사적 대화 및 기억 공유    |
| 신뢰           | 상대 주장 및 약속을 믿는 정도          |
| 존중           | 판단력과 능력에 관한 평가              |
| 경계심         | 자신에게 위협이 될 가능성              |
| 압박감         | 현재 상황의 부담 (감정 상태)           |
| 갈등·보호 의지 | 기존 요구사항의 대립 및 타인 보호 동기 |

0~100 범위와 증감량은 예시다. 공감은 친밀감·신뢰를, 논리적 추론은 존중을 높일 수 있고, 근거 없는 추궁은 경계와 압박을 높일 수 있다. NPC 성격 및 맥락에 따라 달라진다. 동일 행위 반복으로 무한 상승하지 않도록 한다. 수치 전체를 화면에 표시하지 않고 태도·표정·문구로 전달하는 방식을 검토한다. 친밀감이 높다고 자백하거나 압박감이 높다고 반드시 비밀을 공개하지 않는다.

## 믿음과 비밀

객관적 사실, 개인이 실제로 아는 정보, 추측 및 잘못된 믿음을 구별한다. 믿음은 명제 ID, 근거, 출처, 확신 정도, 수정 시점을 포함하는 형태를 검토한다. 도현이 재현의 범행을 강하게 믿다가 피해자의 이후 생존 및 알리바이를 제시받으면 믿음을 수정하고 자백 유지 목표를 재평가한다. 단일 증거가 논리적으로 충분하지 않으면 의심 상태를 유지한다.

비밀은 정보 단위로 공개 범위와 민감도를 관리한다. 공개 요청을 검증하기 전 플레이어 대사나 수첩에 노출하지 않는다. NPC가 자신이 가진 정보에 대해 의도적으로 거짓말하는 것과 잘못 믿는 내용을 진심으로 전달하는 것을 구분한다. 전체 사건 정의나 타인의 비밀을 NPC 문맥에 넣지 않는다.

## 소문과 자율 행동

소문 이벤트에는 발신자, 수신자, 내용, 출처, 사실 확인 상태, 원본 이벤트 ID를 보존한다. 수신자는 자신의 목표·관계·믿음에 따라 전달 여부를 판단한다. 중복 이벤트와 무한 재전달을 막는다. 예: 플레이어가 하린에게 도현의 자백을 의심한다고 말하면 하린이 재현에게 사실 확인을 요청하고 재현이 도현에게 접근할 수 있다.

일상 이동·기본 일정은 규칙 기반으로 실행한다. 중요한 대화 종료, 이동, 증거 발견 등의 이벤트에 관련 NPC만 LLM으로 판단한다. 요청 가능한 행동은 이동, 대화 요청, 정보 전달, 계획 갱신, 증언 수정, 비밀 공개 등으로 제한한다. NPC의 판단은 요청일 뿐 게임 서버가 실행 여부를 결정한다. 필수 증거 파괴나 영구적 진행 차단은 허용하지 않는다.

## 데이터 경계 및 응답 예시

정적 프로필·목표·허용 지식과 세션별 기억·관계·믿음·감정·행동을 분리한다. 다음은 개념 예시다.

```json
{
  "npcId": "harin",
  "profile": { "name": "윤하린", "occupation": "카페 주인", "interests": ["베이킹", "카드 게임"] },
  "goals": { "daily": "카페 운영", "personal": "관계 유지", "case": "범행 은폐" },
  "secrets": [
    {
      "id": "S_HARIN_01",
      "factId": "F_HARIN_FALSE_TESTIMONY",
      "sensitivity": "high",
      "disclosedTo": []
    }
  ],
  "beliefs": [],
  "memories": [],
  "relationships": { "player": { "affection": 45, "trust": 35, "respect": 20, "wariness": 25 } },
  "emotion": { "stress": 30, "mood": "composed" }
}
```

LLM 응답 개념 예시:

```json
{
  "dialogue": "조사관님도 참 끈질기시네요.",
  "detectedIntent": "interrogation",
  "emotion": "defensive",
  "relationshipProposal": { "trust": -3, "respect": 2, "wariness": 5 },
  "memoryCandidates": [
    { "type": "interaction", "summary": "플레이어가 사건 당시 행적을 물었다.", "importance": 0.7 }
  ],
  "disclosureRequests": [],
  "beliefUpdateRequests": [],
  "actionRequests": []
}
```

서버는 형식·권한·출처·공개 범위를 검증한다. 허용되지 않은 사실을 포함한 생성 대사는 그대로 표시하지 않고 재생성 또는 안전한 대체 응답으로 처리한다. 수치 범위 및 상태 변경 역시 검증한다.

## 검증 항목

- 사건 외 대화에서 인물별 성격과 관심사가 구별되는지.
- 중요한 실제 발언을 이후 회상하고 존재하지 않는 기억은 만들지 않는지.
- 친밀감과 신뢰가 독립적으로 변하고 반복 입력에 악용되지 않는지.
- 잘못된 믿음이 적절한 증거에 의해 수정되는지.
- 모르는 사실 및 비공개 비밀이 프롬프트 공격이나 자유 대화로 유출되지 않는지.
- 전달 이벤트가 출처를 보존하고 중복 처리되지 않는지.
- NPC가 관계에 따라 다른 행동을 요청하지만 사건 진실은 유지되는지.
- 실제 MCP·Skills 연동과 응답 지연·호출 비용을 검증하는지.
