## 2. 논의 내용

### 초기 개발 범위

전날 제안한 단일 사건 유형 우선 구현 방안을 검토하였다.

여러 유형을 동시에 개발하기보다 하나의 유형에서 사건 및 NPC 생성과 전체 게임 진행을 먼저 검증하는 방향에 동의하였다.

### 역할 분담 변경

기존의 플레이어·NPC 중심 역할 분담은 두 시스템 간 의존성이 높아 코드 충돌과 중복 작업이 발생할 가능성이 있었다.

이에 김민경이 역할 분담 변경을 제안하였으며, 게임 시스템과 AI 에이전트 시스템을 분리하는 방향으로 협의하였다.

### 프로젝트 문서 및 저장소 정리

- 윤청우가 GitHub 연동 방법을 공유하고 초기 AGENTS.md, PRD.md, TodoList.md를 작성하여 등록
- 김민경이 PRD 양식 변경 및 디렉터리 구조 개선 제안
- 윤청우가 협의된 역할 분담, 저장소 구조 및 협업 규칙을 문서에 반영
- 김민경이 수정된 PRD를 검토하고 진행에 동의

### GitHub 협업 방식

협업 과정의 가독성을 높이고 상호 검토를 보장하기 위해 커밋, 브랜치 및 PR 관리 방식을 논의하였다.

김민경이 상대 팀원의 승인을 요구하는 PR 설정과 Squash Merge 설정을 적용하였다.

## 3. 결정 사항

### 개발 범위

- 초기에는 사건 유형 1개를 우선 구현
- 핵심 기능 완성 후 추가 사건 유형 검토
- 단일 유형 내에서 AI가 사건과 NPC를 생성하도록 하고 정상 작동 여부를 우선 확인

### 역할 분담

| 담당 | 담당 영역 |
| --- | --- |
| A (김민경) | AI 에이전트, NPC 로직, 기억·관계·행동 판단, MCP 클라이언트, Agent Skills |
| B (윤청우) | 게임 시스템, UI·UX, 그래픽, 게임 상태 관리, MCP 서버 |
| 공동 | 세계관·사건·NPC 설정, 공통 데이터 및 API 설계, 협업 관리, 통합 테스트, 발표 준비 |

NPC의 대화 생성과 행동 판단은 A가, 대화 인터페이스와 AI 응답의 화면 반영은 B가 담당한다. (A·B 표기는 당일 수정된 PRD 기준)

### 저장소 구조

- `agent/` — 팀원 A
- `game/` — 팀원 B
- `shared/` — 공동 작업
- `docs/` — 프로젝트 문서 및 회의록

### 협업 규칙

- 커밋 메시지 및 PR 제목은 `type(scope): 요약` 형식 사용
- 커밋 메시지 설명은 한국어로 작성
- 담당자와 Issue 번호를 기준으로 브랜치 관리
- PR 댓글을 통해 검토 및 개선 의견 공유
- 상대 팀원 승인 후 Squash Merge
