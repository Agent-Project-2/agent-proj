이는 실제 완료 실적이 아닌 작성 분담 제안이다. 공통 내용과 최종 계약은 상대가 검토한다. 한 사람이 문서 양식·구조를 정리한 경우 그 작성 기여를 보존하고, 다른 사람은 담당 항목을 보완하며 문서 전체를 자신의 작업으로 다시 작성하지 않는다.

문서별 작성 책임자를 지정하고 상대가 검토하는 방식도 허용한다. 위 항목별 표는 기본 제안이며 팀 합의로 문서 단위 분담을 선택할 수 있다. 실제 작성자는 작성 기여를, 검토자는 검토 기여를 남기고 검토만으로 공동 작성자가 되지는 않는다.

| 작업일 | 기여 유형·작업 범위 | 실제 작성자 | 이슈·커밋·PR | 검토·검증 근거 |
| ------ | ------------------- | ----------- | ------------ | -------------- |

실제 작업 후 행을 추가한다. 공동 작업도 작성 영역과 실제 검토자를 구분하고, 기획·설계·구현·문서·리뷰·통합 검증을 따로 식별한다. 회의록·ADR에는 실제 참여와 결정만 남긴다.

- 각자는 자신의 Git 작성자와 GitHub 연결 이메일을 확인한다. 상대 작업을 대신 커밋하거나 과거 작성자·날짜를 바꾸지 않는다.
- Squash 방침을 유지하고 검증 가능한 작업 단위로 기간 중 PR을 남긴다. 병합 전후 작성자·실제 공동 작성자·연결 이슈를 확인한다. 공동 결정이나 리뷰 참여만으로 코드 공동 작성자를 추가하지 않는다.
- 형식적 커밋 수를 늘리지 않는다. 제공된 평가 기준의 코드 내용, 기간 전체의 작업 분포, 이슈·PR 기록을 실제 작업 근거로 보여준다.
- AI 활용 과정은 사용 도구·작업 범위·틀린 결과·수정 과정·검증 결과를 기록한다. API 키·개인정보·원본 민감 대화는 첨부하지 않는다.
- 평가에 쓰는 README·발표에는 최초 아이디어 제안, 후속 공동 구체화, 실제 작성·구현·검토를 구분한다. 알려지지 않은 초기 자료와 기여는 확인 대기로 표시한다.
